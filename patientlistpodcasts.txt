9:T6ca,AI Patient List Podcasts is a clinician-facing workflow that turns the last 12 hours of patient activity into concise, playable audio briefings. Instead of requiring physicians to scan multiple dashboard views and chart fragments before rounds, the experience packages high-signal events into per-patient podcast items that can be consumed quickly while context-switching between tasks.

The frontend is a Next.js/React application that starts a PromptJob from a physician prompt and then incrementally renders progress as outputs become available. Under the hood, a Flask-based LangChain orchestration layer coordinates tool calls that fetch time-bounded events, draft scripts, synthesize speech, and persist artifacts. Azure Functions provide the typed API boundary for jobs and podcast items, Cosmos DB stores operational and content state, and Azure Blob Storage serves generated audio via secure URLs.

The design emphasizes production reliability as much as generation quality: idempotent job creation, per-patient retries, partial completion visibility, and traceable request IDs across stages. The UI polls job and item endpoints to surface progress without blocking the entire workflow, so one slow patient script does not stall the rest of the list. This makes the system resilient to noisy clinical data, variable generation latency, and transient downstream failures.

From a product perspective, the goal is not novelty for novelty’s sake; it is decision support in a format that matches real clinical pacing. By combining summarization, event filtering, and text-to-speech in a bounded time window, the project explores how AI can reduce cognitive load while preserving relevance, timeliness, and operational transparency.a:T4ee,This project interests me because it treats "last 12 hours" clinical review as a real-time product problem, not just a model-output problem. Translating fragmented patient events into concise, per-patient audio briefings is a practical way to reduce cognitive overhead without forcing another dashboard workflow.

From an engineering perspective, I like that the hard work is orchestration and reliability, not just prompt writing. The PromptJob lifecycle, per-patient parallelization, retry behavior, and partial-progress rendering all have to work together so the UI remains useful even when one branch is slower or noisy. That combination of agentic sequencing, typed service boundaries, and resilient async UX is exactly the kind of systems design challenge I enjoy.

I am also drawn to the human side of the format. Audio briefings fit naturally into pre-round prep and transition moments, where screen attention is limited but decisions still need to be made.
